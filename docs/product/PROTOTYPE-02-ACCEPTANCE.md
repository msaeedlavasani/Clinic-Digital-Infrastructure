# PROTOTYPE-02 — Acceptance Contract

**Class:** CANONICAL (the gate definition)
**Status:** Recorded only — **do not execute in this task** (`FOUNDATION EXTENSION` stop condition). Execution is authorized only after the Foundation Extension is accepted and Owner signals PROTOTYPE-02.

---

## 1. Mission

Prove the amended Experience Direction (`EXPERIENCE-DIRECTION.md`) and Visual Worlds architecture (`VISUAL-WORLDS.md`) as a continuous, luxurious, medically credible homepage journey — using the Master Catalog for a realistic service universe — **without** production implementation, framework selection, or canonicalization before Owner acceptance.

## 2. Acceptance criteria

### A. Continuous Journey
At least several consecutive homepage viewport-stages (Arrival → Enter → Discover → Treatments → Technology → Expertise → Evidence → Consultation pattern per the continuity contract) — not merely a Hero. Visual continuity between stages must be demonstrable.

### B. Realistic Service Universe
Representative services drawn from the **Master Catalog** must be visibly demonstrated — at minimum categories such as Laser Hair Removal · Dermal Filler · Botox · Skin Rejuvenation · HIFU/RF · a hair-related capability — unless a later Owner decision changes the Noor service mix. Content must follow capability/content separation (clinic-differentiated copy, no Master-primitive text dumped as final).

### C. Real Demo Media
No empty placeholder rectangles for high-fidelity visual judgment. Real temporary reference media (locally stored, provenance recorded) across the journey.

### D. Dark + Light Proof — the critical gate
Use the **same underlying Experience Engine** (geometry/content model) to prove at least:
1. one **Dark** premium expression (e.g. Dark Cinematic), and
2. one **Light/Luminous** premium expression (e.g. Luminous Luxury).
The Light version must be **equally premium**. **If only the Dark expression feels luxurious: DESIGN SYSTEM PROOF = FAIL.**

### E. Mobile
Both directions must have credible mobile behavior — art-directed, not desktop-stacked.

### F. Reduced Motion
The experience must retain quality and full information access with the reduced-motion preference enabled.

### G. No Canonicalization Before Owner Acceptance
No Visual World, palette, motion token, or geometry becomes canonical merely because it was implemented successfully. **Owner visual acceptance is required.** Status after execution: `OWNER_VISUAL_REVIEW_REQUIRED`.

## 3. Explicitly out of scope for PROTOTYPE-02

Production application code · framework/CMS/database/animation-library selection · full website build · Clinic #2 replication execution · consultation form implementation depth beyond the journey stage · canonical token freeze.

Luxury test (craft not decoration) · Clinical test (physician-led credibility) · Distinctiveness test (not a generic premium template) · Image-dependency test (capabilities vs art direction documented) · all §46 PROTOTYPE-01 review gates where applicable · the §28 diversity test applied to the Dark/Light pair (same engine, materially different worlds).
